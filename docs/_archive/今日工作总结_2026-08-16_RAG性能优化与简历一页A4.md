## 二、完成事项

### 1. 面经咨询 / 题库 RAG 检索性能优化 ✅

**分环节实测耗时（`../.venv/Scripts/python.exe`）：**

| 环节 | 实测耗时 | 结论 |
|---|---|---|
| Embedding 模型首载 | 32.0s | 冷启动一次性开销 |
| 标题集合向量查询 | 0.02~0.04s | 快（但当时命中 0） |
| 全文集合查询（首查） | 2.07s | HNSW 索引冷加载 |
| 关键词兜底 `$contains` | 0.34s | 仅标题命中不足时触发 |
| `search_questions` 完整调用（热） | 2.13s | 每次走全文回退路径 |

**根因**：`interview_kb_title` 标题索引集合为空（count=0），而全文集合有 1972 条。设计上应先查标题索引（短文本、快、召回好），为空时回退全文集合查询（长文档、首查 2s）。为空原因是 `_merge_import_banks.py`（最近一次重建库）与 `_ingest_ai_agent_bank.py` 直接 `collection.upsert` 只写全文集合、**漏写标题索引集合**。

**修复动作：**
- `interview_knowledge_base.py` 新增 `rebuild_interview_title_index()`：从全文集合读取 1972 条，解析「题目+考察点」短文本，一次性重建式写入标题集合（遵循项目已验证的"清空后一次性 upsert 可正常落盘"模式）。
- `_merge_import_banks.py` / `_ingest_ai_agent_bank.py`：补写标题索引，防止重建库后再次出现。
- `web_app.py` `_warmup()`：启动时检测标题集合为空则自动重建（自愈），并做一次真实检索把索引加载挪到启动阶段。
- 对真实库执行重建：`title: 0 → 1972`（8s）。

**效果：修复后热路径检索 0.03s，面经咨询阈值场景同样 0.03s（修复前每次 ~2.1s）。**

### 2. 简历一页 A4 约束 ✅

`resume_formatter.py`：

| 措施 | 实现 |
|---|---|
| 内容裁剪 | `fit_resume_to_one_page()`：经历≤3 段、每段≤3 要点；项目≤2 个、每点≤3 条；技能≤4 组每组≤10 项；奖项/证书各≤5 条；摘要≤160 字；单条要点>80 字截断 |
| 学生工作经历优先裁剪 | 公司含"学生/校/学术"识别：真实工作≥3 段时整体裁掉；不足时仅留 1 段且要点≤2 条 |
| 字号收窄 | classic 正文字号 10.6pt→10pt（12 处）、紧凑模式 9.5pt→9pt |
| 紧凑样式 | `.resume-compact` CSS：缩小 padding / 字号 / 行距 / 条目间距 |
| 自适应兜底 | `_ONE_PAGE_FIT_JS`：测量真实渲染高度，先启用紧凑样式，仍超则按比例 zoom（下限 0.6），监听 `beforeprint` |

**验证**：Edge 无头打印 PDF 实测恰好 1 页 A4（595×842pt）。

### 3. 精美简历 Word 化 ✅

`resume_writer.py` / `graph.py`：

- 新增 `write_customized_resume_docx(data, output_docx)`：基于结构化 ResumeData 生成 A4 一页 Word 简历（A4 210×297mm、紧凑边距、微软雅黑 9pt、灰色底纹章节条、日期左/内容右表格版式），渲染前自动执行一页裁剪。

**验证**：Word COM 转 PDF 实测恰好 1 页 A4。

## 三、遇到的问题与解决

| 问题 | 原因 | 解决 |
|---|---|---|
| 检索每次 ~2.1s | 标题索引集合为空 → 每次回退全文集合查询 | 重建标题索引 + 修复两个入库脚本漏写 + 启动自愈 |
| 冷启动 32s+2s | embedding 模型首载 + HNSW 索引冷加载 | 启动预热线程（已有）+ 新增检索预热与标题索引自愈 |
| 日志大量 `WinError 10060` 重试 | 模型加载联网检查 HuggingFace（网络受限） | `start_web_offline.py` / `start_server.bat` 设 `HF_HUB_OFFLINE=1` |
| bash 后台启动的进程被回收 | bash 会话结束时连带终止子进程 | 改用计划任务（schtasks）常驻启动 |
| 28 条要点即使 zoom 0.6 仍 2 页 | 裁剪参数过宽（4 段×4 要点） | 默认收紧为 3 段×3 要点（一页经验容量 15-18 条） |
| docx2pdf / win32com 未安装 | 环境缺依赖 | 用 PowerShell 调 Word COM 转 PDF 验证页数 |
| `test_fail_at_limit_stops` 失败 | 工作区未提交的 graph.py 路由改动（重试超限后仍进 interview）与旧测试预期不符 | 未改动（与本次工作无关，需另行同步测试） |
