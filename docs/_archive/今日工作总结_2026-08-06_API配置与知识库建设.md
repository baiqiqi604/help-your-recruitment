## 三、遇到的问题与解决措施

| # | 问题 | 原因 | 解决措施 |
|---|---|---|---|
| 1 | `pip install chromadb` 下载超时失败 | 官方 PyPI 源（files.pythonhosted.org）网络慢/不稳定 | 改用清华镜像：`pip install <包> -i https://pypi.tuna.tsinghua.edu.cn/simple --timeout 60 --retries 5` |
| 2 | 后台安装进程被回收，日志 0 字节 | bash 会话结束/超时回收了后台进程树 | 改为**前台分步安装**（每步 300 秒上限），利用 pip 缓存与断点续传逐包完成；后续用 `nohup`/PowerShell `Start-Process` 均不可靠，最终以前台分步为准 |
| 3 | 拉勾/猎聘/智联在线静态抓取 0 条 | 反爬拦截：智联 WAF 验证页（`Security Verification`）；猎聘页面 JS 动态渲染，静态 HTML 无岗位卡片 | ① 先加 Cookie 重试（部分生效）；② 最终改用 **DrissionPage 真实浏览器渲染**抓取，绕过 JS 渲染与登录态校验 |
| 4 | Cookie 填了但程序读不到 | 用户把 Cookie 粘贴到了 `.env` 的**注释行**（行首仍带 `#`） | 检查确认后去掉 `#` 注释符，程序正常读取 |
| 5 | 智联有 Cookie 仍被拦截 | WAF 需要滑块/人机验证，纯请求头无法绕过 | 放弃智联，改用猎聘浏览器渲染方案；智联需人工过验证码（未纳入本次数据） |
| 6 | BGE-large 模型（1.3GB）下载反复超时 | HuggingFace 直连被墙/极慢；300 秒 bash 超时反复打断；Xet 分块下载完成慢 | ① 设置 `HF_ENDPOINT=https://hf-mirror.com` 走镜像；② 断点续传推进至 ~4G 仍未完成 → 切换官方轻量模型 `BAAI/bge-small-zh-v1.5`（约 95MB），检索效果接近，建库立即跑通 |
| 7 | 建库报错：`'BGEEmbeddingFunction' object has no attribute 'name'` | chromadb 1.5.9 要求 EmbeddingFunction 实现 `name()` 协议方法 | 在 `jd_knowledge_base.py` 的 `BGEEmbeddingFunction` 增加 `name()` 静态方法 |
| 8 | 检索报错：`'BGEEmbeddingFunction' object has no attribute 'embed_query'` | chromadb query 流程要求 `embed_query()` | 补充 `embed_query()` 方法 |
| 9 | 检索报错：`Unsupported input type: list` | chromadb 调用 `embed_query(input=[query_text])` 时传入的是**列表**，原实现按单个字符串处理产生嵌套列表 | 修改 `embed_query` 签名兼容 `str \| list[str]` 两种入参 |
