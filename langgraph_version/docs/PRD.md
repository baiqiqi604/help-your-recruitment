# 简历优化 Agent（LangGraph 版）— 产品需求文档 PRD

> 文档阶段：产品概念版（MVP）
> 状态：方向已确认，技术选型为 LangGraph 图编排
> 依据：《简历优化 Agent_技术开发文档.md》v1.1、《简历优化Agent_PRD_初版.md》

## 一句话定位

面向求职者的简历优化工具：自动聚合网络岗位形成岗位知识库，用户选定目标 JD 后，
由 **LangGraph 流水线**自动生成保留原版格式、可继续编辑、且不编造经历的定制简历，
并提供一个带 **多轮对话记忆** 的 Agent 助手全程辅助。

## 产品形态

- **当前选型**：Web App（FastAPI）+ 命令行（CLI）双入口。
- **选择理由**：每日后台抓取、岗位推荐、多轮对话记忆均需要持续运行的服务端能力；网页形态降低使用门槛。
- **阶段策略**：MVP 支持 DOCX 与可提取文本的 PDF；后台每日从 BOSS 直聘、智联招聘、猎聘、拉勾获取岗位；
  用户选定岗位后经 LangGraph 流水线生成简历并在页面编辑，最终导出 PDF。

## 目标用户

- **核心用户**：准备秋招、春招或毕业求职的应届生；缺乏针对不同岗位改简历的方法和时间。
- **次级用户**：求职辅导者或职业顾问，需要基于同一份真实简历高效产出多个岗位版本。
- **当前痛点**：用户往往基本不修改简历就直接海投；即使看到岗位 JD，也不知道该改哪些内容、突出哪些经历。

## 产品价值

- **对用户**：从海量岗位中发现与简历更匹配的机会，快速获得可编辑、保留原始格式的定制简历，减少盲目海投。
- **对产品**：免费提供核心能力以提升知名度；通过岗位浏览、选择、导出等匿名化行为数据验证产品价值。
- **商业模式**：首期免费使用；后续变现方式暂不定义。

## MVP 核心功能

1. **简历解析与读取**
   - 上传 DOCX 或可提取文本的 PDF；系统提取技能、项目、教育与求职意向线索。
   - 复杂 PDF、扫描件给出明确降级提示。

2. **岗位知识库（RAG）**
   - 后台每日定时爬取岗位；去重、标记大厂与高频岗位后向量化入库（ChromaDB + BGE）。
   - 支持按岗位描述、技能、公司名语义检索；提供大厂/高频优质岗位推荐。

3. **岗位选择与结构化分析**
   - 用户从推荐/检索结果中选择目标 JD，或手动粘贴 JD。
   - 从 JD 中提取必备技能、加分技能、职责、经验要求与关键词（`jd_analyzer`）。

4. **定制简历生成（LangGraph 流水线）**
   - `load_resume → analyze_jd → optimize → review → write_output` 五节点流水线。
   - `review` 节点由 LLM 审核优化结果是否达标：不达标且未超重试上限则回到 `optimize` 迭代；超限则终止并给出意见。
   - 生成内容必须关联原始简历事实；无原文证据时使用【待确认】标记，不得编造。

5. **对话 Agent（多轮记忆）**
   - 基于 `create_react_agent` + `MemorySaver`，同一 session_id 内可连续追问（如“分析这段 JD”“它要求哪些技能”“帮我改这段经历”）。
   - Agent 可调用 4 个领域工具：分析 JD、优化简历、检索岗位、获取优质岗位。

6. **版本导出与留存**
   - 优化结果写回 Word（保留原格式），可选导出 PDF。
   - 原始简历、生成 Word、导出 PDF 自创建之日起保留 7 天（数据留存策略后续细化）。

## MVP 不做什么

- 不绕过反爬机制，不保存招聘平台账号、Cookie、验证码信息，不规避平台访问限制。
- 不承诺通过 ATS、获得面试或提高录用概率。
- 不自动补充用户未提供的公司、职位、技能、职责、时间或量化成果。
- 不支持扫描型 PDF OCR、批量投递、多语言简历与复杂 PDF 的完全还原。

## 成功标准（初版）

| 指标 | MVP 目标 | 说明 |
|---|---:|---|
| 事实一致率 | 100% | 所有被采纳的事实性表述均可关联原简历证据。 |
| 任务成功率 | >= 90% | 合法 DOCX/文本型 PDF 从上传、选岗、生成、编辑到导出的完整链路成功。 |
| 岗位更新成功率 | [待确认] | 每日任务中成功完成并通过质量校验的数据源比例。 |
| 优化流水线稳定性 | 高 | 任一节点异常不崩溃，经条件边/重试机制兜底到可交付结果。 |
| 单次完成时长 | [待确认] | 含模型调用与导出，不含用户审阅时间。 |
| 格式保真度 | [待确认] | 需定义原版格式保留的验收标准（字体、样式、段落、表格、分页）。 |

## 待确认问题

- 第三方模型的选型、用户告知、脱敏策略和传输范围如何定义？
- 各平台合规的数据接入方式、刷新频率、数据保留与删除规则如何定义？
- 被多次查看岗位写入 RAG 的阈值、去重策略与保留期限如何定义？
- 原版格式保留的验收范围是什么；复杂 PDF 无法高保真时是否提示用户上传 DOCX？
- 重试上限（当前 `MAX_ATTEMPTS=3`）与审核通过阈值是否需要按模型/场景动态调整？
