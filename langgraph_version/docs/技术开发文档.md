## 1. 项目背景与目标

### 1.1 背景

求职过程中，不同岗位对简历的侧重点各不相同。一份简历投递多个岗位，往往因匹配度不足而无法通过初筛。
本项目通过 **RAG（检索增强生成）+ 大模型 + 图编排** 实现自动化简历优化，提升简历与岗位匹配度，
同时保留原始排版格式，并提供带多轮记忆的对话助手。

### 1.2 目标

| 功能 | 说明 |
|------|------|
| 多平台岗位爬虫 | 每日定时从 BOSS/拉勾/猎聘/智联爬取岗位，失败不崩溃 |
| 岗位知识库（RAG） | ChromaDB + BGE 存储岗位全文，支持语义检索与优质岗位推荐 |
| PDF 简历解析 | pdf2docx 转换 + python-docx 提取文本与格式 |
| 岗位需求分析 | LLM 提取必备技能、加分技能、职责、经验要求、关键词 |
| **简历优化流水线** | **LangGraph StateGraph 五节点编排，含 LLM 审核与重试条件边** |
| **对话 Agent** | **LangGraph ReAct Agent + MemorySaver，按 session 多轮记忆** |
| 格式保留输出 | 优化结果写回 Word 保留格式，可选导出 PDF |

## 4. LangGraph 优化流水线设计（重点）

### 4.1 State 定义

使用 `TypedDict` 定义节点间流转的共享状态（`graph.py`）：

```python
class OptimizeState(TypedDict, total=False):
    resume_text: str                      # 简历纯文本
    jd_text: str                          # 岗位描述全文
    jd_analysis: dict[str, Any]           # 岗位分析结果
    optimized_text: str                   # 优化后的简历全文
    matching_table: list[dict[str, Any]]  # 简历-JD 匹配关系表
    error: str                            # 错误信息
    attempts: int                         # 审核重试次数
    review_verdict: dict[str, Any]        # 内部：审核结论 {"pass": bool, "feedback": str}
```

### 4.2 节点设计

| 节点 | 函数 | 职责 |
|------|------|------|
| `load_resume` | `load_resume(state)` | 校验输入非空、超长截断、归一化 `resume_text`/`jd_text` |
| `analyze_jd` | `analyze_jd(state)` | 调用 `jd_analyzer.analyze_jd` 产出结构化 `jd_analysis` |
| `optimize` | `optimize(state)` | 调用 `content_optimizer.optimize_resume_content` 优化简历 + `build_matching_table` 构建匹配表 |
| `review` | `review(state)` | 调用 LLM 审核优化结果，返回 `pass/fail + feedback`；失败时 `attempts + 1` |
| `write_output` | `write_output(state)` | 汇总最终状态快照，供 `run_optimize` 返回 |

### 4.3 边与条件边（文字设计图）

```
                    ┌──────────────────────────────────────────────┐
                    │                 START                        │
                    └─────────────────────┬────────────────────────┘
                                          ▼
                                  ┌───────────────┐
                                  │  load_resume  │
                                  └───────┬───────┘
                                          │ (普通边)
                                          ▼
                                  ┌───────────────┐
                                  │  analyze_jd   │
                                  └───────┬───────┘
                                          │ (普通边)
                                          ▼
                        ┌─────────────────────────────┐
                        │  optimize                   │
                        │（优化简历 + 构建匹配关系表）   │
                        └──────────────┬──────────────┘
                                       │ (普通边)
                                       ▼
                        ┌─────────────────────────────┐
                        │  review（LLM 审核）          │
                        │  pass/fail + feedback        │
                        └──────────────┬──────────────┘
                                       │ (条件边 route_after_review)
              ┌────────────────────────┼────────────────────────┐
              │                        │                        │
          pass│                   fail且                  fail且
              │              attempts<3                  attempts>=3
              ▼                        ▼                        ▼
     ┌──────────────┐         ┌──────────────┐        ┌──────────────┐
     │ write_output │◄────────│   optimize    │        │     END      │
     └──────┬───────┘  (attempts+1 后)        │        │（重试超限）   │
            │                                │        └──────────────┘
            ▼                                │
     ┌──────────────┐                        │
     │     END      │                        │
     └──────────────┘                        │
                                            └────────────────────────┘
                                        （回到 optimize，最多 MAX_ATTEMPTS=3 次）
```

对应代码（`graph.py`）：

```python
graph.add_node("load_resume", load_resume)
graph.add_node("analyze_jd", analyze_jd)
graph.add_node("optimize", optimize)
graph.add_node("review", review)
graph.add_node("write_output", write_output)

graph.set_entry_point("load_resume")
graph.add_edge("load_resume", "analyze_jd")
graph.add_edge("analyze_jd", "optimize")
graph.add_edge("optimize", "review")
graph.add_conditional_edges("review", route_after_review, {
    "write_output": "write_output",
    "optimize": "optimize",
    END: END,
})
graph.add_edge("write_output", END)
```

### 4.4 重试与容错

- 路由函数 `route_after_review`：`pass → write_output`；`fail 且 attempts<3 → optimize`（attempts+1）；超限 → `END`。
- 每个节点内部 `try/except`：单节点异常写入 `error` 字段并尽力降级（如匹配表失败置空），不使整图崩溃。
- `run_optimize` 对最终输出做 `setdefault` 规整，保证调用方字段齐全。
- `build_graph` 以 `@lru_cache` 单例缓存，编译一次多次复用。

## 5. 对话 Agent 设计（重点）

### 5.1 构建方式

`agent.py` 使用 LangGraph 预构建 ReAct Agent：

```python
from langgraph.checkpoint.memory import MemorySaver
from langgraph.prebuilt import create_react_agent

agent = create_react_agent(
    model=get_llm(),             # ChatOpenAI（DeepSeek/OpenAI/通义/智谱）
    tools=TOOLS,                 # 4 个领域工具
    checkpointer=MemorySaver(),  # 会话检查点 → 多轮记忆
)
```

`get_agent()` 以 `@lru_cache` 单例缓存；`MemorySaver` 为内存级检查点存储，
保存每一轮 `messages`（含 AI 工具调用中间消息）的完整快照。

### 5.2 工具定义（LangChain 版语义，`@tool` 装饰器）

| 工具 | 签名 | 语义 |
|------|------|------|
| `analyze_jd` | `(jd_text) -> dict` | 调用 `jd_analyzer.analyze_jd` 提取结构化岗位需求 |
| `optimize_resume` | `(resume_text, jd_text) -> dict` | 调用 `graph.run_optimize` 执行完整优化流水线 |
| `search_jobs` | `(query, top_k=10) -> list` | 调用 `jd_knowledge_base.search_jds` 语义检索岗位 |
| `get_premium_jobs` | `(limit=20) -> list` | 调用 `jd_knowledge_base.get_premium_jobs` 获取优质岗位 |

### 5.3 记忆机制（MemorySaver + thread_id）

LangGraph 的 **检查点（Checkpoint）** 机制是记忆的核心：

1. 每次 `invoke` 都带 `config={"configurable": {"thread_id": session_id}}`。
2. 系统把本轮输入、Agent 思考/工具调用过程、最终回复作为一个 **检查点** 存入 `MemorySaver`，
   以 `thread_id` 为键隔离不同会话。
3. 下一次同 `thread_id` 的 `invoke`，Agent 自动从检查点恢复历史消息上下文，实现多轮记忆。
4. 不同 `session_id` 之间互不干扰（会话隔离）。

```
调用1: chat_with_agent("帮我分析这段JD", session_id="s1")
       invoke(messages=[user:...], config={"thread_id": "s1"})
       → MemorySaver 存检查点 thread_id="s1"（含历史）

调用2: chat_with_agent("它要求哪些技能？", session_id="s1")
       invoke(messages=[user:...], config={"thread_id": "s1"})
       → 从检查点恢复上一轮上下文 → 正确接续回答

调用3: chat_with_agent("你好", session_id="s2")
       → 新 thread_id，独立上下文（会话隔离）
```

注意：`MemorySaver` 为**进程内存存储**，进程重启后记忆清空。
生产环境可替换为持久化检查点存储（如 `SqliteSaver` / `PostgresSaver`）。

## 6. 核心模块设计

### 6.1 简历读取（resume_reader.py）

- `pdf_to_docx(pdf_path, docx_path)`：pdf2docx 转换，保留排版。
- `read_resume(docx_path)`：python-docx 提取段落（含字体信息）、表格与 `full_text`。

### 6.2 输出（resume_writer.py）

- `write_optimized_resume(original_docx, optimized_text, output_docx)`：按行顺序替换，保留首 run 格式。
- `docx_to_pdf(docx_path, pdf_path)`：docx2pdf 导出（需本机 Word）。

### 6.3 岗位知识库（jd_knowledge_base.py）

- `BGEEmbeddingFunction`：sentence-transformers 加载 BGE，实现 ChromaDB EmbeddingFunction 协议。
- `init_kb()` / `build_jd_knowledge_base()`：读磁盘 JSON → 去重 → 标记大厂/高频 → 全量入库。
- `add_jobs(jobs)` / `increment_update(jobs)`：按 `job_id` 去重增量入库。
- `search_jds(query, top_k)`、`get_job_by_id(job_id)`、`get_premium_jobs(limit)`：检索接口。

### 6.4 爬虫（jd_crawler.py）

- `crawl_jobs(keyword, city, platforms)`：多平台爬取，单平台失败不影响其他平台。
- `save_jobs(jobs, tag)`：按日期存档 JSON；写入异常不崩溃。
- 四级降级策略：DrissionPage 浏览器监听 → httpx+Cookie → HTML 解析 → 本地策展数据兜底。

### 6.5 定时任务（scheduler.py）

- `daily_crawl_task()`：按关键词列表爬取 → 去重标记 → 存档 → 增量更新知识库。
- `start_scheduler()`：APScheduler `BlockingScheduler` 每日定时执行。

## 10. 待解决问题与风险

- `MemorySaver` 内存级记忆在进程重启后丢失；生产环境需换持久化检查点。
- 重试上限 `MAX_ATTEMPTS=3` 为固定值，审核阈值依赖模型输出质量，需按场景调参。
- 爬虫依赖平台页面结构，反爬与合规需持续评估。
- 复杂 PDF 格式还原保真度存在上限，必要时引导用户上传 DOCX。
