## 3. LangChain Agent 设计（核心）

### 3.1 构建方式

```python
from langchain.agents import AgentExecutor, create_tool_calling_agent
agent = create_tool_calling_agent(llm, TOOLS, prompt)   # Tool-calling Agent
executor = AgentExecutor(agent=agent, tools=TOOLS, memory=memory, ...)
```

- LLM 使用 `llm_client.get_llm()`（多 Provider ChatOpenAI，支持 tool calling）
- Agent 负责「推理 → 调工具 → 观察 → 再推理」，无需人为编排工具调用顺序

### 3.2 工具设计（4 个）

| 工具 | 调用的模块 | 输入 → 输出 |
| --- | --- | --- |
| `search_jds_tool` | `jd_knowledge_base.search_jds` | `(query, top_k)` → 岗位列表 |
| `get_premium_jobs_tool` | `jd_knowledge_base.get_premium_jobs` | `(limit)` → 优质岗位列表 |
| `analyze_jd_tool` | `jd_analyzer.analyze_jd` | `(jd_text)` → 结构化分析 dict |
| `optimize_resume_tool` | `content_optimizer.optimize_resume_content` | `(resume_text, jd_analysis)` → 优化后简历文本 |

设计要点：
- 工具输入输出用**普通 Python 类型注解**，LangChain 自动生成 JSON Schema 供模型调用
- 工具内部捕获异常返回友好信息，避免 Agent 流程中断
- 工具粒度 = 一个可独立复用的业务动作，便于 Agent 灵活组合（如「先查岗位 → 再看 JD → 再优化简历」）

### 3.3 记忆设计

```python
memory = ConversationBufferMemory(memory_key="chat_history", return_messages=True)
```

- `memory_key="chat_history"`：与 Prompt 中的 `MessagesPlaceholder(variable_name="chat_history")` 对齐
- `return_messages=True`：以消息列表形式存入对话历史，保留角色与多模态语义
- **会话隔离**：`chat_with_agent(user_input, session_id)` 用 `dict` 按 `session_id` 缓存各自的 `AgentExecutor`（每个 Executor 持有独立 memory），实现多会话互不干扰
- `get_agent()` 用 `@lru_cache` 缓存 Agent 单例，避免重复构造

### 3.4 提示词要点

- `system`：说明 Agent 身份（简历优化+求职助手）与四个能力，明确「中文回答」「不编造信息」
- `MessagesPlaceholder("chat_history")`：注入多轮记忆
- `("human", "{input}")`：当前轮用户输入
- `MessagesPlaceholder("agent_scratchpad")`：**必须保留**，承载 Agent 中间推理与工具调用记录（tool calling 协议要求）
- 工具 docstring 使用中文，写清参数与返回结构，帮助模型正确选参

## 4. 数据流

### 4.1 岗位入库

```
jd_crawler.crawl_jobs(keyword, city)
   → save_jobs(jobs)                # data/crawled_jobs/jobs_YYYY-MM-DD.json
   → jd_knowledge_base.add_jobs(jobs)
       ├─ id 去重（已有 id 跳过）
       ├─ 公司 ∈ BIG_TECH_COMPANIES → premium=True
       └─ 同岗位出现频次 ≥ HIGH_FREQUENCY_THRESHOLD → premium=True
```

### 4.2 简历优化

```
resume_reader.read_resume(path)           # .pdf/.docx/.txt → 文本
   → jd_analyzer.analyze_jd(jd_text)      # LLM 提取结构化要求
   → content_optimizer.optimize_resume_content(resume, analysis)  # 优化全文
   → content_optimizer.build_matching_table(resume, analysis)     # 匹配表
   → resume_writer.write_optimized_resume(text, out.docx)         # 结构化 docx
   → resume_writer.docx_to_pdf(out.docx, out.pdf)                 # 可选
```

## 5. API 设计

| 方法 | 路径 | 请求 | 响应 |
| --- | --- | --- | --- |
| GET | `/` | - | `templates/index.html` |
| POST | `/api/chat` | `{messages, session_id}` | `{reply}` |
| POST | `/api/optimize` | `{resume_text, jd_text \| job_id}` | `{optimized, matching_table, jd_analysis}` |
| GET | `/api/jobs/search` | `?q=&top_k=` | `{count, jobs}` |
| GET | `/api/jobs/premium` | `?limit=` | `{count, jobs}` |

`/api/optimize` 中 `job_id` 分支：`get_job_by_id(job_id) → jd_text → analyze_jd → optimize_resume_content → build_matching_table`。

## 7. 部署

### 7.1 环境准备

```bash
pip install -r requirements.txt
cp .env.example .env   # 填写 LLM_PROVIDER 与 API Key
```

### 7.2 启动

```bash
# Web（生产可用 uvicorn 直启）
python main.py web
# 或指定端口
python main.py web --host 0.0.0.0 --port 8000

# CLI 对话
python main.py chat

# 定时爬虫（独立进程）
python -m scheduler
```

### 7.3 生产建议

- **反向代理**：Nginx/Caddy 代理 8000 端口并启用 HTTPS
- **进程守护**：systemd / supervisor 托管 `main.py web` 与 `scheduler`
- **Embedding 加速**：有 GPU 时设 `EMBEDDING_DEVICE=cuda`
- **数据备份**：`data/chroma_db` 与 `data/crawled_jobs` 定期备份
- **限流与反爬**：爬虫遵守 `CRAWLER_CONFIG.request_interval`；如站点反爬升级，可扩展 DrissionPage/Playwright 渲染抓取（`jd_crawler` 已预留）

## 8. 扩展点

- **更多招聘平台**：在 `jd_crawler._CRAWLERS` 注册新爬虫函数
- **更多 Agent 工具**：在 `agent.TOOLS` 中追加 `@tool` 函数即可
- **PDF 布局还原**：`resume_writer` 已输出结构化 docx，可扩展富排版模板
- **多轮深挖**：可替换 `ConversationBufferMemory` 为 `ConversationSummaryBufferMemory` 等以控制上下文长度
